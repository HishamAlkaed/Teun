<objective>
Complete the RAG loop: add the top-K cosine retriever, extract inline.rs's
streaming machinery into a shared module, build `run_rag` (embed query →
retrieve → single Anthropic Messages call → two-phase MortgageAnswer +
ToolEvidence), repoint both chat modes at it, and delete the dead `run_claude`
subprocess + whole-corpus inline dump (and the Node/claude CLI from the image).

Purpose: This is where the cost win lands — prompts drop from ~100K tokens (or a
full agent session) to only the top-K chunks — while the SSE/MortgageAnswer
contract stays byte-identical and the deferred-verifier option-A mitigation
(ToolEvidence from chunk ranges) keeps citation verification working.

Output: `rag::store::search`, `agent/stream.rs`, `agent/rag.rs`, a repointed
`chat.rs`, deletion of `claude.rs` + the inline corpus loader, and a Node-free
Dockerfile.
</objective>

<execution_context>
DELIBERATE BEHAVIOR CHANGES in this plan — the executor and SUMMARY must call these out:

1. **Verifier boundary (CONTEXT-locked):** do NOT modify `judge/verifier.rs`. It
   still reads from disk (Phase 3 rewires it to `documents.extracted_text`).
   The option-A mitigation is REQUIRED: `run_rag` builds `ToolEvidence` from the
   retrieved chunks' line ranges and returns it; chat.rs passes it into
   `judge::run_judge`, and the RAG prompt formats chunks with visible canonical
   line numbers so the model cites real ranges. Degraded PDF-quote verification
   is an accepted Phase-1 gap.

2. **Judge retry loop dropped:** the current tools-mode `search_depth=uitgebreid`
   behavior re-runs the whole agent up to `max_retries` when the judge score is
   low (chat.rs:232-321). That retry loop depended on the re-runnable claude
   subprocess. On the single-call RAG path it is removed — every request is a
   single pass + one judge call (keep only the existing error-retry wrapper for
   transient API failures). This is an intentional simplification; note it in the
   SUMMARY so eval-runner expectations are re-baselined.

3. **The inline SSE streaming loop is NOT a callable helper today** — it is
   inlined inside `run_inline` (inline.rs:207-274). "Reuse" therefore means
   EXTRACT it (plus `parse_two_phase_response`) into `agent/stream.rs` first
   (T2), preserving logic byte-for-byte, then call it from run_rag. The
   extraction happens BEFORE T4 deletes inline.rs internals.
</execution_context>
