<objective>
Extract PDF text with pdfium-render into the line-numbered canonical body +
line→page map that the whole citation chain depends on, and bundle the PDFium
native library into the Docker image so extraction works at runtime.

Purpose: The canonical body IS the citation contract (verifier + DocumentViewer
are line-number based). This is also the phase's highest-risk item — PDFium
Docker bundling is LOW confidence and must be spiked before the ingest pipeline
(Plan 03) depends on it.

Output: `src/rag/extract.rs`, a reworked Dockerfile runtime stage, and a
verified end-to-end extraction on the seed PDFs.
</objective>

<interfaces>
<!-- The line model verifier.rs expects (Phase 3 will point it at this text). -->
- verifier.rs treats a document as `content.lines()`, 1-indexed. The canonical body's lines MUST match this model: one `\n`-terminated line per logical line, no line-number prefixes stored in the body itself.
- RESEARCH Pattern 1 gives the exact shape: `struct Canonical { text: String, page_of_line: Vec<u32> }` where `page_of_line[i]` = 1-indexed source page of 0-indexed line i. See 01-RESEARCH.md "Pattern 1" and Pitfall 1 (PDFium loading) / Pitfall 2 (extraction quality).
- pdfium-render API (verify exact borrow signatures on docs.rs at implementation): `Pdfium::new(...)`, `pdfium.load_pdf_from_byte_slice(bytes, None)?`, `doc.pages().iter()`, `page.text()?.all()`.
</interfaces>
</context>

    - build_canonical over a 2-page fixture: page_of_line has one entry per line of text; lines from page 1 map to page 1, page 2 lines to page 2.
    - page_of_line.len() equals text.lines().count().
    - Empty/garbled page does not panic — yields an empty or best-effort body and a matching (possibly empty) page map.
  </behavior>
  <action>
Create `src/rag/extract.rs`. Define `pub struct Canonical { pub text: String, pub page_of_line: Vec<u32> }`. Implement `pub fn build_canonical(doc: &PdfDocument) -> anyhow::Result<Canonical>` per RESEARCH Pattern 1: iterate `doc.pages().iter()`, for each page push each `page.text()?.all()` line into `text` (append `\n`) and push the 1-indexed page number into `page_of_line`. Implement `pub fn extract_from_bytes(bytes: &[u8]) -> anyhow::Result<Canonical>` that binds Pdfium once — `Pdfium::bind_to_library(Pdfium::pdfium_platform_library_name_at_path("/app")).or_else(|_| Pdfium::bind_to_system_library())` (research Pitfall 1) — loads the PDF from the byte slice, and returns the canonical body plus `page_count`. Guard against oversized input (reject > 50 MB) and cap pages (e.g. 2000) per the security domain; treat pdfium errors as `Err`, never panic. Register `pub mod extract;` in `rag/mod.rs`. Add a tiny 2-page text-only PDF fixture under `apps/teun/service/tests/fixtures/` (document how it was generated in `fixtures/README.md`) and write the behavior-block tests (mark `#[ignore]` only if they require the native lib on the host; keep pure line/page-map assertions runnable).

</threat_model>
